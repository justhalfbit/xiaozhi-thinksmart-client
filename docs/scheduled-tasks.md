# 动态定时任务

固定提醒（例如“下午五点提醒我取快递”）沿用 `self.alarm.create(kind=reminder)` 与预先合成的语音，到点不调用模型。动态任务（例如“每天早上七点播报当天天气”）使用 `self.task.create`，到点才请求网关查询或生成结果。网关结合两类工具指导当前对话模型按用户意图选择；创建阶段仍使用当前对话模型，没有另外的关键词分类器。

## 工具与使用

- `self.task.create`：必填 `instruction`、`tools`；时间、日期和重复规则复用现有提醒约定。天气用 `get_weather`，最新信息用 `web_search`，纯内容生成传空列表。未给执行钟点时先向用户澄清。
- `self.task.list`：读取安排及最近执行；查询所有安排时也读取 `self.alarm.list`。
- `self.task.cancel`：删除任务并停止本次执行。
- `self.task.stop`：仅停止当前执行，保留后续重复。

首页按时间显示待执行提醒与动态任务，以及正在查询/等待/播报的任务。设置页显示安排、最近执行文本、来源和失败原因，支持停止以及二次确认删除。用户唤醒、发起文字提问、普通闹钟响铃或试听铃声时会打断当前任务，避免阻塞新交互。

## 持久化与播报

任务单独存储于用户数据目录的 `tasks.json`，不改变原有 `alarms` 数据格式。最多保存 100 项安排和最近 50 项终态执行。一次发生的执行标识和下一次时间在网络请求之前原子写入，防止进程重启后重复查询或播报。重启时未完成执行标记为中断，不自动重试。时间未同步时暂停调度；错过一小时内补执行一次，更久则记录错过。

任务串行执行，查询最长等待 125 秒；结果等待对话、闹钟、试听或睡眠时段结束，最多十分钟。长结果完整保留（最多 1200 字），按句子边界拆为每次不超过 200 字的 TTS 请求，只预取下一段。播报沿用提醒音量，完成或取消后恢复音量、屏幕和音频状态。停止会取消待合成片段及对应网关执行。

## 部署与验证

需要支持 `/kiosk/tasks/run` 和 `/kiosk/tasks/cancel` 的配套网关，且网关与客户端同机运行。旧网关会返回明确的不支持错误；固定提醒继续走原实现。动态任务首版仅支持网关已配置的 OpenAI 兼容 API 模型和既有天气/搜索工具，不增加依赖或上传个人配置。

运行 `python -m pytest tests`。新增测试覆盖独立数据存储、重复安排推进、重启防重跑、错过处理、写盘失败、停止/删除、固定提醒触发时零模型请求、长文本完整分段及取消预取。页面交互应验证首页任务更新、停止和确认删除。音频硬件、真实服务、整机重启与跨天自然触发需要另外人工验证。本 PR 保留上游发布版本，由维护者安排版本发布。
